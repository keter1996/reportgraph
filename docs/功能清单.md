# 功能清单

ReportGraph 是面向 Power BI PBIP 项目的可安装图谱工具链，用于把报表结构、模型结构、页面关系、字段绑定与 Markdown 文档沉淀为本地 `Graph/` 产物，并通过统一命令与 MCP 边界对外提供能力。

## 当前能力

- 从 PBIP 项目初始化 Report Graph。
- 从 `.pbip` 文件路径或 PBIP 项目目录解析报表结构。
- 读取 PBIR 报表定义中的页面、视觉对象和视觉字段绑定。
- 读取语义模型中的表、列、度量值和关系。
- 支持 `model.bim` 与基础 TMDL 语义模型目录。
- 生成 `Graph/report-graph.json` 作为结构化图谱产物。
- 生成 `Graph/manifest.json` 作为版本、路径、指纹与生成元数据。
- 生成 `Graph/dirty-state.json` 作为宿主通知或 watch 脏标记状态。
- 生成 Markdown 上下文文件，方便人工阅读和 Agent 消费。
- 基于稳定源文件集合判断 stale，而不是只靠粗粒度计数。
- 跟踪 `.pbip`、`*.Report/**`、`*.SemanticModel/**` 和纳入范围的 `.md` 文件。
- 排除 `Graph/`、`.pbi/`、`bin/`、`obj/`、`node_modules/` 与隐藏文件，避免误刷新。
- 提供项目诊断能力，用于验证 PBIP 入口、图谱状态、dirty 状态和 stale 原因。
- 提供 CLI 命令入口。
- 提供 MCP stdio 服务入口，基于官方 .NET `ModelContextProtocol` SDK。
- 提供自包含发布脚本，适合客户机器或自动化安装场景。
- 提供 `codex-install.json`，用于机器可读安装描述。

## CLI 命令

- `reportgraph init`
- `reportgraph doctor`
- `reportgraph update`
- `reportgraph delete`
- `reportgraph status`
- `reportgraph mark-dirty`
- `reportgraph query`
- `reportgraph watch`
- `reportgraph mcp`
- `reportgraph install-info`

## 查询能力

- `query graph`
- `query page <pageId>`
- `query page-intent <pageId>`
- `query page-context <pageId>`
- `query page-bindings <pageId>`
- `query measure <measureName> [tableName]`
- `query measure-lineage <measureName> [tableName]`
- `query term-search <keyword>`
- `query document <documentIdOrPath>`
- `query table <tableName>`
- `query visual <pageId> <visualId>`
- `query explore <from-page|from-table> <identifier>`

## 自动刷新与变更触发

- `doctor`：只诊断，不刷新。
- `status`：只显示状态，不刷新。
- `query`：如果 `manifest` 缺失、`graph` 缺失、源文件指纹变化，或存在 dirty 标记，则自动刷新。
- `mcp`：每次工具调用前遵循同一套自动刷新判断。
- `mark-dirty`：只标记 dirty，不立即重建。
- `watch`：监听稳定源文件集合，默认只标记 dirty，也可通过 `--refresh` 直接刷新。

## 当前边界

- 仓库不附带业务 PBIP 项目。
- 使用者需要用自己的 PBIP 项目执行初始化、诊断、更新和查询。
- `Graph/` 是生成产物，通常不建议提交到 Git。
- Power BI Desktop 的 `.pbi/` 本地状态文件不参与图谱稳定性计算。
- 当前对外能力边界仅面向 PBIP 项目，不包含 PBIX 解析。
