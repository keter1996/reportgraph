# 使用说明

## 1. 安装

推荐使用自包含发布方式：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\publish-reportgraph.ps1
```

发布完成后，可执行文件位于：

```text
artifacts\publish\win-x64\reportgraph.exe
```

查看命令：

```powershell
.\artifacts\publish\win-x64\reportgraph.exe --help
```

## 2. 初始化图谱

进入你的 PBIP 项目目录：

```powershell
cd <your-pbip-project-root>
reportgraph init
```

也可以显式传入项目目录或 `.pbip` 文件：

```powershell
reportgraph init <your-pbip-project-root>
reportgraph init <your-report.pbip>
```

初始化后会生成：

```text
Graph\
  manifest.json
  report-graph.json
  dirty-state.json
  context\
    report-summary.md
    model.md
    bindings.md
    pages\
      <pageId>.md
```

## 3. 项目诊断

```powershell
reportgraph doctor
reportgraph doctor <your-pbip-project-root>
reportgraph doctor <your-report.pbip>
```

`doctor` 会检查：

- PBIP 入口和项目结构
- 报表目录与语义模型目录
- Markdown 文档扫描结果
- `Graph/` 产物是否存在
- 当前 stale 状态与 stale 原因
- 当前 dirty 标记与源文件跟踪数量

`doctor` 只诊断，不会自动刷新。

## 4. 查看状态

```powershell
reportgraph status
reportgraph status <your-pbip-project-root>
```

`status` 会显示：

- `Graph/` 目录、图谱文件和 manifest 是否存在
- 当前是否存在 dirty 标记
- 当前是否 stale
- stale 原因
- 跟踪的源文件数量
- 已生成图谱的基础摘要信息

`status` 也不会自动刷新。

## 5. 更新图谱

普通更新：

```powershell
reportgraph update
```

强制重建：

```powershell
reportgraph update --force
```

指定项目：

```powershell
reportgraph update <your-pbip-project-root> --force
```

## 6. 标记 Dirty

如果宿主或人工已经知道项目源发生了变化，但暂时不想立刻重建，可以只打 dirty 标记：

```powershell
reportgraph mark-dirty
reportgraph mark-dirty <your-pbip-project-root>
reportgraph mark-dirty <your-pbip-project-root> --reason "Changed outside ReportGraph"
```

打标后，下一次 `query` 或 MCP 工具调用会自动刷新，并清掉 dirty 状态。

## 7. 查询图谱

查询完整图谱：

```powershell
reportgraph query graph
```

查询页面：

```powershell
reportgraph query page <pageId>
```

查询页面意图：

```powershell
reportgraph query page-intent <pageId>
```

查询页面上下文：

```powershell
reportgraph query page-context <pageId>
```

查询页面绑定：

```powershell
reportgraph query page-bindings <pageId>
```

查询度量值：

```powershell
reportgraph query measure <measureName> [tableName]
```

查询度量值血缘：

```powershell
reportgraph query measure-lineage <measureName> [tableName]
```

查询术语：

```powershell
reportgraph query term-search <keyword>
```

查询 Markdown 文档索引节点：

```powershell
reportgraph query document <documentIdOrPath>
```

查询表使用情况：

```powershell
reportgraph query table <tableName>
```

查询视觉对象：

```powershell
reportgraph query visual <pageId> <visualId>
```

轻量探索：

```powershell
reportgraph query explore from-page <pageId>
reportgraph query explore from-table <tableName>
```

`query` 会在以下情况下自动刷新图谱：

- `manifest.json` 缺失
- `report-graph.json` 缺失
- 稳定源文件指纹发生变化
- 存在 dirty 标记

刷新时会输出原因，例如：

```text
Auto refreshed graph: Source fingerprint changed.
Auto refreshed graph: Marked dirty by watch.
```

## 8. Watch 模式

本地开发时，可以监听稳定源文件集合：

```powershell
reportgraph watch
reportgraph watch <your-pbip-project-root>
reportgraph watch --debounce-ms 3000
reportgraph watch --refresh
```

说明：

- 默认模式：仅标记 dirty，不立即刷新。
- `--refresh`：检测到变化后直接刷新。
- `--debounce-ms`：控制连续保存时的防抖时间，默认 `2000` 毫秒。

监听范围与图谱指纹一致，包括：

- `.pbip`
- `*.Report/**`
- `*.SemanticModel/**`
- 纳入范围的 `.md`

不会监听为有效源变化的内容包括：

- `Graph/`
- `.pbi/`
- `bin/`
- `obj/`
- `node_modules/`
- 隐藏文件

## 9. 启动 MCP

```powershell
reportgraph mcp
```

如果使用发布产物：

```powershell
.\artifacts\publish\win-x64\reportgraph.exe mcp
```

宿主可以通过 MCP stdio 连接该进程，并调用 ReportGraph 提供的查询工具。

支持的 MCP 工具包括：

- `report.graph.load`
- `report.graph.status`
- `report.graph.mark_dirty`
- `report.page.get`
- `report.page.intent`
- `report.page.context`
- `report.page.bindings`
- `report.measure.get`
- `report.measure.lineage`
- `report.term.search`
- `report.document.get`
- `report.model.table.get`
- `report.visual.get`
- `report.graph.explore`

MCP 工具调用与 `query` 使用同一套自动刷新规则。

## 10. 删除图谱

```powershell
reportgraph delete
reportgraph delete <your-pbip-project-root>
```

## 11. Git 建议

建议提交：

- `src/`
- `tests/`
- `docs/`
- `scripts/`
- `codex-install.json`
- `README.md`
- `README.en.md`

不建议提交：

- `bin/`
- `obj/`
- `artifacts/`
- `Graph/`
- `.pbi/`
- 用户业务 PBIP 项目
